## 1. 目标与边界

本次工作按照《A题 GitHub 候选阶段审计》修复 F01–F07 及其点名的配置、报告、图和文档残留，使候选数值、实际运行配置、验证证据和输出检查之间可追溯且不会静默分叉。

以下内容保持不变：

- 题给物性公式、节点型 FVM、变系数散度形式、Q1/Q23 初值关系；
- Q4 参考坐标、内部扩散 `1/R²`、表面项 `1/R` 和固定长度假设；
- 全节点未舍入阈值判据、四位小数只用于输出；
- `production.approved=false`，本次不构成 D12 授权；
- 生产续算与正式 `result1–4` 导出继续如实标记为未实现、未生成。

本次不重建主物理模型，不新增机理或无意义的灵敏度全组合扫描，也不修改用户未跟踪的 MATLAB 图片。

## 2. 总体方案

采用“统一契约、增量返修”方案，在现有模块边界内增加三个明确接口：

1. **有效运行配置**：每次求解先解析出该问实际使用的完整数值配置，并保存不可变快照。
2. **有界同源轨迹**：事件段与续算段组合为一个有严格时间边界的轨迹，所有事件、表值和文件采样从该轨迹读取。
3. **结构化验证记录**：验证函数返回机器可判定的状态、指标、限值、配置、覆盖范围和最差位置，Markdown 报告只负责渲染这些记录。

主方程和空间算子不重写。配置、求解器、验证、输出和报告通过上述契约连接，避免继续依赖函数默认值或手写“通过”文字。

## 3. 配置与实际运行参数

### 3.1 唯一权威检查器

`src/drymodel/config_check.py` 是唯一校验实现。`建模方案v1.1/config_check.py` 仅保留可独立执行的薄入口，加载项目 `src` 后转调权威实现，不复制规则。

权威检查器使用严格辅助函数校验：

- 数值必须是排除 `bool` 的 `int/float`，并满足有限性和范围；
- 整数项必须是真正整数，覆盖 N、求积点数、Picard 次数和减步次数；
- BDF/BE 容差、步长、包络容差、情景幅度必须为有限正数；
- `max_step_after_s`、`picard.tol_dC` 等审计负例必须拒绝；
- `output.result1–4` 的时间规则、列规则、工作表、A1、格式、表面列和域外规则逐项校验；
- `approved=true` 时，Q1/Q23/Q4 的 `final_N`、实际界面/积分方法、配置标识和验证证据引用必须全部具体，不能只接受任意非空 `config_id`。

普通 Python 和 `python -O` 共用相同显式异常路径。

### 3.2 有效运行配置

在 `config.py` 中引入不可变的分问运行配置对象，至少记录：

- question、purpose（候选/空间对照/时间对照/求积对照/灵敏度）；
- N、界面方法、界面求积点数；
- 时间积分方法、rtol、各 atol、前后段最大步长、断点；
- BE 步长与减步参数；
- 环境情景幅度、`h/hm` 倍率；
- 是否启用累计通量状态。

基线值来自 YAML。网格研究或时间加密通过显式派生配置创建，并在证据中记录差异；求解器装配不再藏有 `integral_npts=8`、`±0.39` 等可配置硬编码。CLI 参数若覆盖配置，也必须进入快照。

配置快照使用规范化 JSON 和稳定摘要标识。未来生产入口除校验 YAML 外，还要核对配置摘要和验证记录一致；本次仍不实现正式生产导出。

## 4. 求解轨迹与失败传播

### 4.1 BDF 有界同源轨迹

`BDFResult.eval()` 在求值前检查：轨迹非空、查询时间有限、查询点位于真实积分闭区间内、返回状态有限。越界直接抛出明确异常，不调用 SciPy 稠密解外推。

事件求解成功后，从事件状态继续积分到所需严格秒点、严格分钟点及 600 s 检查终点。两部分通过组合接口形成单一轨迹；组合时校验时间连续、状态连续、两段成功且实际到达请求终点。Q23/Q4 的：

- `t_cross`、首个严格合格整数秒、首个严格合格分钟；
- result2/result3/result4 采样；
- 表 3–6、阈值诊断、通量和平均量；

全部从该组合轨迹读取，不再从原始初态二次积分。找不到严格合格网格点时返回失败，不以 `ceil` 或非 60 s 后备值替代。

候选轨迹启用累计通量 `I` 时，事件和续算均保留同一状态维数与累计初值，组合不得重置 `I`。

### 4.2 BE 接受子步账本

BE 每个实际接受子步记录 `t0/t1/Δt` 及相邻状态；基础网格步因失败拆成多个子步时，每个子步都进入账本。求解结果区分基础步数、接受子步数和减步次数。

验证调用必须先检查 `result.ok`、有限状态及实际终点。质量残差用每个接受子步的真实 `Δt` 加权步末通量；独立梯形积分同样按不等距时刻计算。热残差取结束于探针时刻的相邻真实状态和真实 `Δt`，不再四舍五入时间或转换为整数。

固定域使用 `R0`，动域使用对应子步时刻的 `R(t)` 和参考体积到物理表面的因子。核心求解器返回失败状态，验证层将其转换为明确的失败记录，禁止未前进轨迹产生零残差“通过”。

## 5. 验证证据与门控

### 5.1 统一验证记录

验证结果采用统一结构，包含：

- `check_id`、`question`、`status`；
- `metric`、`limit` 和判定方向；
- 完整有效配置快照与摘要；
- `coverage`（时间、位置、变量、采样规则）；
- 最大误差及其时空位置；
- 失败原因或未运行原因。

状态仅允许 `pass`、`fail`、`partial`、`not_run`，由数据计算。局部检查只能得到 `partial` 或带明确覆盖范围的 `pass`，不能升级为整项通过。D12 就绪汇总要求适用必检项全部 `pass`；任何 `fail/partial/not_run` 都阻止“可提交 D12”的表述。

同时生成机器可读 JSON 和 Markdown。`verification.md`、`status.md` 不含写死状态；是否执行灵敏度、生产导出和文件验收均根据实际返回值及文件证据决定，不能由 `approved` 单独推断。

### 5.2 验证覆盖

V-1/V-2 分开记录空间解析解和 BE 时间阶，不以一张空间表声称两者全过。

V-3 采用分块求值以限制内存，分别记录空间对照和时间对照：

- Q1：1–1800 s 全部逐秒行、21 个固定位置、C/T、论文表点；
- Q23：result2 全逐秒共同区间、result3 分钟点、21 个固定位置、C/T、表点、表面通量、平均 C、阈值和晚期剖面；
- Q4：全部分钟行、固定厘米列和表面列、域内掩码、表点、表面通量、平均 C、阈值和晚期剖面；必须单列 `r=1.2 cm` 的最差误差位置。

空间对照只改变 N；时间对照固定 N 并使用显式加密配置。两类证据分别判定。

V-4 包含：

- BE 离散代数收支；
- BE 独立梯形通量，报告 `dt=1 s` 粗步未过、`dt=0.25 s` 细步通过及收敛率；
- BDF 候选累计通量状态与外部独立时间求积/加密交叉检查；
- 使用真实相邻状态的热残差；
- Q4 的 `1/R(t)` 动域收支。

V-5 对求解器接受状态和所有输出重构值执行有限性及 C/T 包络检查，记录最差裕量；不能只检查最终时刻。

V-6 的 `delta` 和 `dt_star` 来自实际空间/时间加密差，不再使用 NaN。事件后检查、严格分钟采样、无回穿和采样失败均形成门控结果。

V-11 扩展为配置化的界面/求积对照，覆盖各问适用的表点、通量、平均 C、晚期剖面与时长；Q23 时长网格趋势只是其中一条记录。

## 6. 表格、工作簿与跨文件一致性

表5固定列为：时间、`r=0/0.5/1/1.5/2 cm` 的含水率，共六项；`Cmax` 仅进入诊断记录。表5/6 的 6 h 常规行与 `t*` 末行使用容差去重，末行仍来自同一未舍入轨迹。

工作簿写后读回采用流式逐行校验，不把大型 result2 全表转为列表。校验内容包括：

- 工作表集合及顺序、完整表头逐项数值/文本比较；
- A 列为真实整数、首末值正确、严格连续且无重复；
- 域内单元格为排除布尔的有限数值，数据格式为 `0.0000`；
- 域外单元格为空，result4 表面列每行始终为有效数值并检查格式；
- 完整数据行数和最后一行判据；
- result2/result3 在共同时间、共同位置上的四位舍入结果逐格一致。

错误表头、文本数据、域内空值、错误格式、表面空值、掩码错误和跨文件差异均加入回归测试。

## 8. 测试与完成判据

实现采用失败路径优先的回归方式。至少覆盖：

1. 两入口检查器对合法配置与全部审计变异给出相同结果，普通与 `-O` 一致；
2. 求积点数和敏感性幅度变更会改变实际装配/情景；
3. `approved=true` 但缺最终 N 或验证证据时被拒绝；
4. BE 强制减步、完全失败和 `dt=0.5 s` 热残差；
5. BDF 上下界越界、失败/未到终点、组合连续性和累计 `I` 保留；
6. 表5六列、Cmax 分离、表5/6 末行去重和严格采样失败；
7. 工作簿的表头、类型、格式、空值、表面列、掩码、末行及 result2/3 跨文件负例；
8. 验证状态由指标生成，未运行/局部/失败不能被报告器提升；
9. Q4 `r=1.2 cm` 全行空间对照及独立时间对照；
10. 原有测试全部继续通过，主候选关键数值在合理容差内复现。

完成前执行逐项审计：把 F01–F07 和审计返修要求 1–10 分别映射到代码、测试、运行记录、报告或明确的“仍未执行”状态。最终回报按“已修复并实测通过／仍未执行／仍失败／待用户授权”分类，附实际配置、最大误差及其时空位置。
